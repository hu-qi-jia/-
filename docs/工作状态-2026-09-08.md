### ★ P1 落盘为 0 阻塞问题:已定位修复(2026-09-08 晚)
**根因**:会话键字段错位 —— content script 把 `sessionKey`/`buyerIdTail` 放在**事件级**(`ev.sessionKey`),而 `pddCapture.ts` 对 msg 事件只读**消息级**(`m.sessionKey`,`PddCapturedMsg` 上恒 undefined)→ 所有 DOM 消息被判 `nosession` 跳过,分段器从未执行到(content script 从不发 `active`,`tabSessions` 兜底永远为空)。
**修复**:`pddCapture.ts` 改读 `ev.sessionKey ?? m.sessionKey`(及 buyerIdTail 同样兼容),`pddSegmenter.SegMsg` 增加 `buyerIdTail` 透传到问答记录。
**验证**:新增 `tests/unit/background/pddCapture.test.ts` 3 例(TDD 先红后绿);40/40 单测过;tsc 0 错;真浏览器合成链路 qaCount 0→1、msgId 幂等(`dupmsgid`)正常、错误表干净;**用户在自己 Chrome 真机验收:问答记录正常增长** ✓

### 排查期曾误导方向的两个环境坑(重要教训,以后遇到先查这两条)
1. **SW 跑陈旧代码**:rebuild 后浏览器可能仍执行旧 SW 脚本(响应缺新增字段即证据,如无 `detail`)。登录态 profile 尤其顽固,重启浏览器不够;对策:诊断脚本先 `chrome.runtime.reload()` 或让用户 chrome://extensions reload。`scripts/diag-sw-version.mjs` 内置"版本探针"(无 sessionKey 事件 → 新代码应答 `detail:"nosession=1"`)+ login 模式自动 reload。
2. **脚本异常退出污染 profile**:诊断脚本崩溃(未 `ctx.close()`)后,该 profile 的扩展 SW 可能从此起不来(重启也不行)。`.chrome-debug-profile` 已处于此状态(**未修复**,自动化测试改用一次性 profile:`diag-sw-version.mjs` 默认 `personal-ai-memory/.diag-fresh-profile`,污染了就删掉重跑)。人工修复尝试 `scripts/repair-ext.mjs`(chrome://extensions 的 developerPrivate reload),曾卡在 launch 未验证完。
3. 附:SW 内 `chrome.runtime.sendMessage` **不会回送到自身 onMessage**——合成测试必须从扩展页(popup)发,不能 `sw.evaluate` 里发。

## 三、数据链路(现状,已验证)

```
content(pdd-chat-capture,ISOLATED) ──PDD_INGEST{events}──▶ SW
  handlePddIngest: 会话解析(ev.sessionKey ?? m.sessionKey,缺省 tab 兜底)
    → normalize → 保留期过滤 → msgId 幂等(内存 Set,SW 唤醒即清)
    → PddSegmenter(买家连续文本=问题段,客服文本关闭落盘+挂回复;idle/leave 关无回复段)
    → Dexie(QaRecords/Replies) + queueEmbedding(问题向量,offscreen)
```
- 段内异常 → `db.logError()` 落 `errors` 表(常驻:SW 控制台生产不可达,DB 是唯一观测通道);跳过原因计数随响应 `detail` 返回(保留,开销可忽略)
- content 逐行捕获日志已降级到 `DEBUG=false` 开关(`pdd-chat-capture.ts`)
